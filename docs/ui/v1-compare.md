## 三版一句話

| 版本 | 一句話定位 | 檔案 |
|---|---|---|
| A | 極簡文字卡：白底黑字、資訊最少，畫面中央就是「再翻」「停手」兩顆大鈕 | `v1-A.html` |
| B | 夜市桌面：深色暖光、整個畫面是一張攤位桌，袋子、籌碼軌道、市場卡都是圖像化區塊（純 CSS／inline SVG） | `v1-B.html` |
| C | 手機 App 式：頂部 App bar、卡片式資訊區、底部固定操作列（再翻／停手／市場抽屜），單手直向優先 | `v1-C.html` |

## 差異對照

| 比較面向 | A 極簡文字卡 | B 夜市桌面 | C 手機 App 式 |
|---|---|---|---|
| 視覺風格 | 白底、黑框線、粗黑體大數字；籌碼＝文字色塊（收入黑底、黑天鵝紅框） | 深色夜市背景＋暖光、木紋桌面、紅招牌、金幣籌碼、黑天鵝籌碼帶天氣／稽查／跳電圖示、牛皮紙卡片、收據式結算 | 淺灰底、白色圓角卡片、橘色主色、藥丸標籤、進度條式黑天鵝計量、底部 dock |
| 資訊層級（玩家第一眼看到什麼） | 暫存收入 $40 與黑天鵝 2/4 兩個大數字，再往下是兩顆大鈕 | 桌上的袋子（剩 7 顆）與黑板（暫存／黑天鵝燈號／現金），翻出的籌碼是畫面中的實體物件 | 頂卡的 $40 與紅色黑天鵝計量條；底部橘色「再翻」永遠在拇指位置 |
| 資訊密度 | 低：主畫面只放必要數字，市場只有文字列 | 高：所有資訊都在同一張桌上，市場卡帶圖示與說明 | 中：主畫面只有三張卡；市場在手機上收進抽屜、iPad 上為右側常駐面板 |
| 每回合操作步數（觸控動線） | 再翻 ×n → 停手 → 點卡 → 下一回合 ＝ n＋3 下；市場全程可見不需額外點擊 | 同 A：n＋3 下 | iPad：n＋3 下；手機：n＋3 下，回合中想看市場需多點 1 下「市場」再關閉（結算頁不需要） |
| 手機直向（390×844）表現 | 遊玩中畫面一頁裝完（無捲動），文字大、對比高、最好讀；職業選擇頁剛好一頁 | 三個畫面皆一頁裝完；市場 3 張卡在手機上寬僅約 110 px，卡上說明文字 11 px 偏小；氣氛最強 | 遊玩中無捲動，操作列固定在底部最順手；市場抽屜半屏彈出，結算頁購買清單為列表式，最易點 |
| iPad 橫向（1180×820）表現 | 左欄狀態＋大鈕、右欄市場；版面成立但下半部留白多（約 35%） | 利用率最高：袋子／黑板／軌道／大鈕／市場欄整張桌面攤開，幾乎無留白；軌道籌碼放大到 72 px | 左欄資訊卡（兩欄格）＋右側 400 px 市場面板；卡片區下方留白約 40%，像被拉寬的手機畫面 |
| iPad 橫向利用率 | 中 | 高 | 低～中 |
| 44×44 px 觸控目標是否全數達標 | 是（Playwright 量測三畫面兩裝置皆無 <44 px 的可點元素） | 是（同上） | 是（同上） |
| 實作成本（game-engineer 預估） | 低：純 DOM＋少量 CSS，無圖形資產 | 高：約 12 個 inline SVG 圖示、木紋／燈光 CSS、桌面 grid 在兩種裝置換版；未來加「籌碼飛進軌道」動畫最自然但也最花工 | 中：底部 dock、抽屜（scrim＋transform）、iPad 側欄三種佈局規則；無圖形資產 |
| 最大風險 | 太素，缺乏「夜市」主題感；市場只有文字，玩家可能看不出資產卡的差異，購買階段吸引力弱 | 手機直向上資訊擠、市場卡文字小；深色背景在戶外強光下可讀性下降；工時最長、後續改版面最貴 | iPad 橫向像放大的手機頁，主平台（iPad 為主）利用率最差；市場藏在抽屜裡，玩家在翻牌時看不到「翻多少才買得起」，削弱推運氣的目標感 |

## 設計師建議（可建議，不可代選）

- 建議版本：**B**，理由一句話：本案主平台是 iPad 橫向，B 是唯一把整個橫向畫面用好的版本，且「袋子／籌碼是實體物件」最能支撐第 7 節「籌碼翻出時飛進軌道」的觸覺回饋。
- 若製作人想混合：建議「**B 的 iPad 桌面 ＋ C 的手機底部操作列**」——iPad 用 B 的整桌佈局，手機直向改用 C 的固定 dock 承載再翻／停手，市場改成 B 的圖像卡但放在可橫向滑動的列。若擔心工時，先做 A 當可玩原型（G4 第一版），再把 B 的視覺分層蓋上去，A 的 DOM 結構與 B 相容。
